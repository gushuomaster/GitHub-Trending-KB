# gitroomhq/postiz-app

## 一句话说明
把多个社交平台的内容创作、排期、发布和效果分析集中到一个日历，并支持团队协作、API 自动化和自托管。

## 它能做什么
- 在日历中一次撰写内容，再为不同社交渠道调整文案、媒体和平台必填项。
- 定时或立即发布，保存草稿，并在发布失败时显示渠道错误。
- 提供团队评论、审批、重复发布、内容集合、签名与分析。
- 通过公共 API、Webhook、RSS、n8n、Make 和 Zapier 接入自动化。
- 可选 Postiz Cloud，或用 Docker/VPS 自托管并保留完整源码与数据控制。

## 怎么利用
先选择托管版或部署开源版，连接一个社交渠道；输入全局文案、图片和发布时间，Postiz 为每个平台生成预览并允许单独解锁修改，随后按计划发布。最终在同一日历看到发布状态、失败原因和可用的渠道分析，也可让 RSS、Webhook 或自动化平台持续创建帖子。

## 实际例子
**官方 Quickstart → 场景：** 把同一条产品更新排到多个渠道。**输入：** 一段全局文案、一张产品图、已连接的渠道与发布时间。**操作：** 在 Calendar 点击 Create Post，选择渠道，在 Global 标签写一次内容；为 YouTube、Reddit 等补齐专属字段，检查右侧预览后选择 Add to calendar。**输出：** 定时出现在日历中的帖子；发布后状态变为 published，可直接打开线上版本，失败则显示错误。

## 适合谁
管理多个品牌社交账号的内容运营、营销团队，以及需要用 API/RSS 自动发布并要求数据自托管的工程团队。

## 局限 / 注意点
- Postiz Cloud 没有永久免费层，通常提供 7 天试用；自托管版虽不限制渠道、帖子或成员，但要自行维护 PostgreSQL、Redis、存储、备份、升级和安全补丁。
- 自托管连接多数平台需要自己注册开发者应用并等待平台审核，Meta、YouTube、TikTok 等可能耗时数周；AI 功能还需自带模型密钥。源码使用 AGPL-3.0，修改和网络服务场景需遵守许可义务。
