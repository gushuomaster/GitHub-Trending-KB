# Fission-AI/OpenSpec

## 一句话说明
轻量的 Spec-Driven Development 工具，把提案、需求、设计与任务保存进仓库，约束 AI Coding Agent 按可审阅规格实施。

## 它能做什么
- 用 explore、propose、apply、archive 串起变更生命周期
- 在 openspec 目录保存 proposal、requirements、design 和 tasks
- 用场景化需求与差异规格记录行为变化
- 支持既有代码库中的渐进式 brownfield 工作流

## 怎么利用
官方示例：在仓库执行 `/opsx:propose add-dark-mode` 生成提案、规格、设计和任务，人工审阅后运行 `/opsx:apply` 实现，验收完成再 `/opsx:archive` 固化变更记录。

## 实际例子
**场景 → 输入 → 操作 → 输出：** 官方示例：在仓库执行 `/opsx:propose add-dark-mode` 生成提案、规格、设计和任务，人工审阅后运行 `/opsx:apply` 实现，验收完成再 `/opsx:archive` 固化变更记录。

## 关键命令
```bash
/opsx:propose add-dark-mode
/opsx:apply
/opsx:archive
```

## 适合谁
需要让多人或多个 Coding Agent 围绕可审阅规格协作的长期软件项目团队。

## 局限 / 注意点
- 对很小的改动可能增加文档与同步成本；规格本身也可能错误或过期，Agent 勾选任务完成不等于功能已通过测试和业务验收。
