## 13. [[Projects/xerj-org/xerj|xerj-org/xerj]]

**简介：** 自动索引代码、文档、日志、PDF、SQLite 和 CSV，让 Agent 用全文、向量或混合搜索取得精确片段，而不是逐文件 grep 并消耗大量上下文。

**主要功能 / 特点：**

- 用单条 `autoindex` 命令识别目录内容并增量建立带类型的索引。
- 对源码做 tree-sitter 解析，保存符号、签名、文件和行号。
- 提供 BM25、kNN、混合查询、Agent Memory、MCP 与 Elasticsearch 兼容 API。
- 以单个 Rust 静态二进制运行，不依赖 JVM，并可接入现有 Elasticsearch 客户端。

**怎么利用 / 实例：** 在单人开发机启动本地节点，用 `autoindex` 指向项目或资料目录，再运行 `xerj init` 接入 Agent。输入是代码、文档或结构化文件；XERJ 解析并增量索引，输出带文件位置的检索片段、定义结果或供 RAG 调用的 API。 **官方 reference coding 工作流 → 场景：** Agent 要在陌生代码库实现 WAL segment 轮换。**输入：** 当前工程和相似开源仓库。**操作：** 索引这些目录，执行 `xerj search "how do we rotate the WAL segment"`，再让 Agent 阅读命中的实现片段。**输出：** 按相关性排序、带文件和行号的参考代码，Agent 在写代码前复用已验证做法。

**局限 / 注意点：** `--insecure` 会关闭 TLS 和 API Key，所有能访问端口的调用者都是超级用户，只适合绑定本机的单用户开发环境。README 的参考编码收益来自特定实验；对模型已熟悉的热门公共库可能没有收益，甚至有害，不能把倍数当作普遍保证。
