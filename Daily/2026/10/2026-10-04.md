**简介**：给 Coding Agent 加一套“先复用、再删减、最后才新增抽象”的工程约束，减少过度设计和无必要代码。

**主要功能 / 特点**：

- 用 lite/full/ultra 等级控制 YAGNI 与代码审查强度。

**怎么利用**：安装插件并信任两个生命周期 hooks；在开始实现和审查 diff 时启用 ponytail，让 Agent 先搜索现有能力、删除冗余方案，再保留满足需求与安全性的最小改动。

**实际例子**：**可推导用法 → 场景：** Agent 准备用新框架实现一个布尔配置。**输入：** 需求、现有代码和候选 diff。**操作：** 启用 `/ponytail-review`，检查现有组件复用、不必要抽象及变更影响。**输出：** 满足需求的最小补丁与需要保留的测试、验证和错误处理。

**简介**：给 AI coding/design harness 使用的设计语言与 Skill，让 Agent 能系统审查、精修和简化 UI，而不是只凭模糊的“做得更好看”。

**主要功能 / 特点**：

- `/impeccable audit` 查找设计问题。

**实际例子**：**场景 →** 优化结账表单。 **操作 →** 输入 `/impeccable audit the checkout form`，修复后再 `/impeccable polish the checkout form`。 **结果 →** 得到问题清单及经 Agent 精修的表单实现。

**局限 / 注意点**：设计判断仍带主观性；init 会写入 PRODUCT.md，视觉系统另记入 DESIGN.md，需避免把视觉偏好当成产品事实。带 hooks 的宿主可能需要确认项目 hook 信任。

**主要功能 / 特点**：
